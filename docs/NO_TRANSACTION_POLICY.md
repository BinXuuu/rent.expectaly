# 无交易机制说明（NO_TRANSACTION_POLICY）

> 状态：Stage 00 建立。本文档明确记录「意料之中～意租」与姊妹项目「意料之中～意购」在交易能力上的关键差异，防止后续阶段无意中引入超出需求范围的交易/支付/交付功能。

## 1. 用户的明确要求

- 「不要制作交付系统」
- 「纯挂资源的网站」
- 「不允许在平台内交易」

## 2. 具体不做的功能

- 不做购物车、订单、结算、支付网关（即便是像「意购」那样「预留但关闭」的支付功能开关也不做，本项目**不存在**支付相关的数据结构或功能开关）。
- 不做交付/物流/履约状态机。
- 不做 1 对 1 私信/实时聊天系统（见 [PROJECT_REQUIREMENTS.md](./PROJECT_REQUIREMENTS.md) 第 7 节的「获取联系方式」按钮替代方案）。
- 不做房东身份认证/商家入驻/店铺体系。
- 不做佣金、平台抽成、担保交易等任何形式的资金流转。

## 3. 允许存在的「引导线下联系」能力

- 房源详情页展示发帖人自行填写的联系方式（登录后可见），后续沟通、看房、签约、付款均在平台之外完成，与平台无关。
- 平台仅承担信息展示、内容审核与滥用防范职责，不对线下交易的真实性、合法性、履约结果承担责任（对应法律免责声明在 [COMPLIANCE.md](./COMPLIANCE.md) 中记录）。

## 4. 出租（rent）/ 出售（sale）两种类别同等适用本政策

「意租」在原有「出租」类别基础上新增「出售」（`purpose: "sale"`）类别，涉及金额通常远高于月租，因此本政策的约束**同等且更严格地**适用于出售类房源：

- 出售房源同样**不做**任何形式的平台内定金/房款支付、担保交易、过户手续代办或资金托管，过户（rogito）、公证、房款支付等环节均需买卖双方线下自行完成。
- 出售房源的「中介费」「合同」等标签仅作信息展示（如中介费比例、是否已有购房预约合同 compromesso），不代表平台参与或撮合该笔交易。
- 「获取联系方式」按钮的限流与登录门槛机制对出租、出售房源一视同仁，不因出售房源涉及更大金额而放宽或收紧核实义务之外的平台职责。

## 5. 后续阶段的自我检查清单

每个涉及房源/联系人/评论功能的阶段完成后，应对照本文档确认：

- [ ] 未引入任何购物车/订单/支付相关的类型、表、UI 组件
- [ ] 「获取联系方式」功能未演变为站内交易撮合（如站内下单、站内担保支付）
- [ ] 未引入实时消息/私信系统，用户互动仅限公开评论
- [ ] 免责声明与合规提示未被移除或弱化
- [ ] 新增的「出售」类别未引入定金/房款支付、过户代办等超出纯信息展示范围的功能
